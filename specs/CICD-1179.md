## Goal

Report SOAtest execution violations, including visual differences and change impacts, so failed tests are not incorrectly shown as passing in Jenkins.

## In Scope

- Include every violation type allowed under `ExecViols`: `ExecViol`, `UnitViol`, `FuncViol`, `RuntimeViol`, `ChangeImpact`, and `VisualDifference`.
- Preserve violation messages and available details in the generated xUnit failure. (inferred)
- Match violations to the corresponding test and, for multiple test cases, the corresponding test-case ID. (inferred)
- Cover the affected transformation with regression tests and retain compatibility with existing report formats. (inferred)

## Out of Scope

Not explicitly defined in Jira.

## Behavior

- A test with a `VisualDifference` under `ExecViols` is reported as failed.
- `ChangeImpact` and every other execution violation type listed in the source schema are included in failure reporting.
- Modern SOAtest reports match execution violations by `testId`; when a test has multiple test cases, matching also uses `tcId`. (inferred)
- A single violation retains its message and available `violationDetails`; multiple violations for one test case are combined into one failure with all messages and available details. (inferred)
- Passing tests do not acquire failures belonging to another test or test-case ID. (inferred)
- Existing test names, durations, suite totals, legacy SOAtest handling, and unit-test conversion remain compatible. (inferred)

## Edge Cases

- Single-test-case reports, such as the attached Safari report, must include visual comparison failures. (inferred)
- Multiple test cases for the same test must keep their violations separate. (inferred)
- A test may contain multiple violation types and violations without optional detail text. (inferred)

## Corrections and Additions

This section records repository-derived design decisions separately from the original Jira description.

- The defect was caused by the modern SOAtest transformation selecting only `FuncViol` in both the single-test-case and multiple-test-case paths.
- Both selections include all direct violation children of `ExecViols`, retaining the existing ID filters and failure formatting. This follows Jira's requirement to report anything under that container and avoids another type-specific omission.
- The legacy `FunctionalTests/FuncViols` format retains its existing path; the reported defect concerns `Exec/ExecViols`.
- A compact representative report fixture derived from the attached report and schema list covers every violation type, mixed violations, optional details, and test-case isolation.
